# ADR-0011 — Internationalization from day one

- **Status:** Accepted (2026-10-03)

## Context

Docs and code are in English. Users are Albanian-speaking staff and students; official documents
are in Albanian (and English for the diploma supplement). Q-17 (answered 2026-10-03): Albanian is
the default UI language, English the second, user-switchable. Retrofitting i18n later is expensive.

## Decision

- Use **next-intl**. All UI strings come from message catalogs `messages/sq.json` and
  `messages/en.json`, namespaced by module (`"stu.list.title"`).
- Locales: **`sq` (default)** and `en`. The default is the `DEFAULT_LOCALE` setting, so changing it
  is configuration, not code. Locale stored per user; switcher in the app shell.
- Dates/numbers formatted with `Intl` using the active locale and `Europe/Tirane` time zone.
- Enum labels (statuses, roles) are translated via catalog keys, never displayed raw.
- Official document templates (PLT-09) are separate from UI catalogs and have their own language.

## Consequences

- Every feature adds its strings to both catalogs. The default-locale catalog (`sq`) must be
  complete (CI fails otherwise); `en` may lag, and `pnpm i18n:check` lists missing keys.
- Switching the default language later is a config change.
