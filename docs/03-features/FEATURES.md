# Feature registry

The single list of everything we will build. **This file is the source of truth for feature
status, dependencies and blockers.**

- **Brief** of each feature: `modules/<prefix>.md` (linked from the Feature column).
- **Full spec** (requirements + design + tasks), written just before building: `specs/<ID>-<slug>.md`.
- **Questions**: [../04-open-questions.md](../04-open-questions.md).
- **Roadmap** (why this order): [../05-roadmap.md](../05-roadmap.md).

## Columns

| Column | Meaning | Maintained by |
|---|---|---|
| Status | `todo` → `specced` (spec written & reviewed) → `in-progress` → `done` | you / Claude, by hand |
| Readiness | 🟢 `ready` — nothing blocks it, all dependencies done · 🟡 `waiting` — not blocked, but a dependency isn't done yet · 🔴 `blocked` — an open **blocking** question · 🟠 `blocked-dep` — a dependency is blocked · ✅ `done` | **computed** — `node scripts/features.mjs --write` |
| Depends on | Features that must be `done` first | by hand |
| Questions | Related open questions. Only **blocking** ones (see questions file) affect readiness; non-blocking ones mean "built on a working assumption" | by hand |
| Source | Requirement IDs in [../00-source/requirements-en.md](../00-source/requirements-en.md) | by hand |

"No blockers" = 🟢 + 🟡 (can be built in order). "Blockers" = 🔴 + 🟠 (need an answer first).
