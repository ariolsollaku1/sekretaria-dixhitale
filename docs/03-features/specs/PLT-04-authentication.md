## 1. Context

Users sign in through Keycloak; the app decides access ([ADR-0004](../../02-architecture/adr/0004-keycloak-auth.md),
[auth.md](../../02-architecture/auth.md)). Candidates and alumni never log in (SRC-030, SRC-037).
Roles/permissions are PLT-05; user administration is IAM-01. This feature delivers login, session,
logout and the Keycloak realm as code.

## 2. Requirements

### User stories

- As a **staff member or student**, I want to sign in with my LOGOS account, so that I can use the
  system securely.
- As a **sysadmin**, I want accounts that weren't created in the app to be refused, so that nobody
  gets in by just having a Keycloak login.
- As a **user**, I want "Sign out" to really sign me out, so that a shared computer is safe.

### Acceptance criteria

| ID | Criterion |
|---|---|
| AC-1 | WHEN an unauthenticated user requests any page under `(app)`, THE SYSTEM SHALL redirect to `/login?callbackUrl=<path>`. |
| AC-2 | WHEN the user clicks "Sign in", THE SYSTEM SHALL start an OIDC authorization-code flow with PKCE (S256) and `state` against realm `logos`, client `sekretari-web`. |
| AC-3 | WHEN Keycloak returns a valid code for a person whose verified email (first login) or Keycloak `sub` (later logins) matches an **active** app `User`, THE SYSTEM SHALL create a DB-backed session, link the `sub` on first login, and redirect to `callbackUrl` (same-origin only) or `/`. |
| AC-4 | IF no active app `User` matches, THEN THE SYSTEM SHALL NOT create a user or session, SHALL show `/no-access` with a support hint, and SHALL end the Keycloak session. |
| AC-5 | THE SYSTEM SHALL issue the session cookie as `httpOnly`, `sameSite=lax`, and `secure` when `APP_URL` is https. |
| AC-6 | WHILE a session is idle longer than `SESSION_IDLE_MINUTES` (default 30) or older than `SESSION_MAX_HOURS` (default 12), THE SYSTEM SHALL treat it as expired. |
| AC-7 | WHEN the user signs out, THE SYSTEM SHALL delete the app session and redirect to Keycloak's end-session endpoint with `id_token_hint` and `post_logout_redirect_uri=APP_URL/login`, so a new login requires credentials. |
| AC-8 | WHEN a user is deactivated (`User.active=false`), THE SYSTEM SHALL reject their existing sessions on the next request. |
| AC-9 | THE SYSTEM SHALL keep the realm configuration in `infra/keycloak/realm-logos.json` (clients, policies per auth.md: no self-registration, email login, brute-force detection, password policy, OTP required for users in group `require-otp`, locales `sq` + `en`) and import it on first start. |
| AC-10 | WHERE `NODE_ENV=development`, THE SYSTEM SHALL provide dev users (one per role, documented in README) created in Keycloak via a dev-only realm file and matching app `User` rows via `pnpm db:seed --env dev`. |
| AC-11 | THE SYSTEM SHALL provide `getCurrentUser()` (nullable) and `requireUser()` (throws → redirect to login) for server components, actions and route handlers. |
| AC-12 | WHEN a login succeeds, is denied, or a logout happens, THE SYSTEM SHALL record an auth event (wired to the audit log once PLT-07 exists; until then a structured server log without personal data). |

### Out of scope

Roles and permission checks (PLT-05), user CRUD and Keycloak provisioning (IAM-01), production
bootstrap of the first sysadmin (IAM-01), Keycloak theme/branding (later), Entra ID brokering (Q-04).

### Assumptions

- Login identifier = email (Q-19). Students may use a personal or `@kulogos.edu.al` address — no
  difference for the design.

## 3. Design

### Library

**Better Auth** with its generic OAuth/OIDC plugin configured for Keycloak (discovery URL
`${KEYCLOAK_ISSUER}/.well-known/openid-configuration`, scopes `openid email profile`, PKCE on).
Email/password and social providers **disabled**; implicit sign-up **disabled**; account linking
by verified email limited to the `keycloak` provider. Store sessions in Postgres via the Prisma
adapter. **Check the current Better Auth docs** for exact option names (they change between
versions). If a requirement cannot be met, fall back to `openid-client` + an encrypted session
cookie and keep the same public API (`getCurrentUser`, `requireUser`, `signIn`, `signOut`).

### Data model

```prisma
// prisma/schema/auth.prisma — generated by the Better Auth CLI, then adapted to our conventions
model User {
  id            String    @id @default(cuid(2))
  email         String    @unique
  emailVerified Boolean   @default(false) @map("email_verified")
  name          String
  active        Boolean   @default(true)
  personId      String?   @unique @map("person_id")     // FK added when Person exists (STU-01/HR-01)
  locale        String?                                  // UI preference (PLT-06)
  lastLoginAt   DateTime? @map("last_login_at")
  createdAt     DateTime  @default(now()) @map("created_at")
  updatedAt     DateTime  @updatedAt @map("updated_at")
  sessions      Session[]
  accounts      Account[]
  @@map("users")
}
// Session, Account (providerId="keycloak", accountId=<sub>, idToken kept for logout), Verification — per library
```

### Flow & components

| Kind | Name | Purpose |
|---|---|---|
| lib | `src/lib/auth/server.ts` | Better Auth instance (server-only) |
| lib | `src/lib/auth/session.ts` | `getCurrentUser()` (React `cache` per request), `requireUser()` |
| lib | `src/lib/auth/guards.ts` | sign-in hook: allow only active users; idle/max-age check |
| route | `src/app/api/auth/[...all]/route.ts` | library handler (callback, session) |
| proxy | `src/proxy.ts` (Next.js "proxy", formerly middleware) | optimistic redirect to `/login` when no session cookie on `(app)` routes — real check stays in `requireUser()` |
| page | `src/app/(public)/login/page.tsx` | LOGOS-branded page with one "Sign in" button; shows reason messages (expired, signed out) |
| page | `src/app/(public)/no-access/page.tsx` | explains the account isn't enabled; link to sign out of Keycloak |
| action | `signOutAction` | deletes session, builds Keycloak end-session URL |
| infra | `infra/keycloak/realm-logos.json` | realm, clients, policies, `require-otp` group with OTP required action |
| infra | `infra/keycloak/dev/realm-logos-dev-users.json` | dev users only (never in prod image/profile) |
| seed | `prisma/seed/dev-users.ts` | app `User` rows matching dev Keycloak users |

Keycloak realm settings (summary — full list in [auth.md](../../02-architecture/auth.md#keycloak-realm)):
SSO idle 30 min / max 12 h aligned with AC-6; brute-force: lockout after 5 failures for 15 min.

### Edge cases & errors

- `callbackUrl` must be a relative path on our origin (open-redirect protection).
- Keycloak unreachable → `/login` shows "Sign-in service unavailable", health reports degraded.
- Email changed in Keycloak after linking → matching is by `sub`, so the user still gets in; IAM-01
  keeps emails in sync.
- Two app users with the same email can't exist (`@unique`).

**Implementation notes (deviations from the first design):**
- Better Auth **1.7.12**, core `signInSocial` + the `genericOAuth` plugin (`providerId: "keycloak"`,
  OIDC discovery, PKCE, `disableSignUp`, `requireEmailVerification`). Sign-in goes through a
  server action (`signInAction`), not the browser client. `nextCookies()` sets cookies from actions.
- Linking: Keycloak is **not** in `trustedProviders`, so first-login linking by email needs
  Keycloak's `email_verified`; `requireLocalEmailVerified: false` because admin-created users have
  no verified flag. Later logins match by `sub` (`accounts.account_id`).
- Inactive users are refused in `databaseHooks.session.create.before` (library error redirect to
  `/no-access`); every request re-reads `users.active` in `getCurrentUser()` (no cookie cache).
- Sessions: `expiresIn` = idle minutes with `updateAge` 60 s (sliding); the absolute limit is
  checked in `getCurrentUser()` from `created_at`. OAuth tokens are stored encrypted; the ID token
  is kept for logout.
- **AC-4 end of the Keycloak session:** a denied login has no account row, hence no `id_token_hint`.
  `/no-access` links to Keycloak's logout endpoint with `client_id` and `post_logout_redirect_uri`
  only; Keycloak asks the user to confirm. Normal sign-out (AC-7) uses the hint and needs no click.
- **AC-9 OTP:** realm role `require-otp` is granted by group `require-otp`; a custom browser flow
  (`browser-logos`) adds `Condition - user role` → `OTP Form`. Users without a configured OTP are
  prompted to set one up. Group membership for sysadmins is IAM-01's job.
- **AC-10 dev users:** realm import is all-or-nothing, so dev users are not in a second realm file.
  `infra/keycloak/dev/dev-users.json` is the single source; `scripts/keycloak-dev-users.mjs`
  (run by `pnpm infra:up`) adds them through Keycloak's partial-import API and
  `prisma/seed/dev-users.ts` creates the matching app users. Role assignments arrive with PLT-05.
- Realm placeholders `${APP_URL}`, `${APP_URL_ALT}` (the containerized app), client secrets come
  from the Keycloak container environment. Changing the realm file needs `pnpm infra:reset`.
- `/(app)` pages are protected by `src/proxy.ts` (cookie presence) plus `requireUser()`.
- UI copy lives in `src/lib/auth/copy.ts` (sq/en) until PLT-06 introduces next-intl.
- E2E needs the compose stack (Keycloak), so it runs locally (`pnpm infra:up && pnpm test:e2e`), not
  in the CI job, which has only a Postgres service.
- **Bug found and fixed on the way (PLT-03 follow-up):** Prisma's pg adapter sends dates as UTC
  strings without offset and Postgres read them in the session zone (`TZ=Europe/Tirane`), shifting
  every stored timestamp by 2 h. Fix: `createAdapter()` pins the session to UTC and the `db`
  service runs `-c timezone=UTC`. Regression test: `timestamps.int.test.ts`.
- `env` is now validated lazily (first use and in `instrumentation.ts`), so `next build` works
  without runtime variables.
