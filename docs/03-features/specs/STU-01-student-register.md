## 1. Context

SRC-040: the Main Register (*Regjistri Themeltar*) holds every student; SRC-020: their personal
data, confirmed at registration (the candidate typed it at application, ADM-04 later feeds this);
SRC-023: the NIM is generated by the Ministry's SMIAL and, until the integration (INT-01), typed
in by the Secretariat. The `Person` entity was introduced by HR-01 and is shared: a lecturer who
studies is one person with a staff record and a student record. Cohorts and groups (ORG-04) say
where a student belongs; status changes (suspension, deregistration, graduation) are STU-02, which
builds on the enrollment status and its history table created here.

## 2. Requirements

### User stories

- As the **Secretariat or Student Affairs**, I want to register a student with their personal data
  and enroll them in a program and cohort, so that the Main Register is complete.
- As the **Secretariat**, I want to register the student for each academic year in a year of study
  and group, so that lists, timetables and obligations follow.
- As **finance, quality, heads of department and coordinators**, I want to find students by program,
  year, group, status and other criteria within my scope.
- As a **student**, I want to see my own record.

### Acceptance criteria (EARS)

| ID | Criterion |
|---|---|
| AC-1 | THE SYSTEM SHALL store a `Student` per `Person` with a generated internal `studentNumber` (zero-padded 6-digit sequence, unique, never reused) and an optional unique `nim` (upper case, ≤ 30 characters). |
| AC-2 | THE SYSTEM SHALL store enrollments with the student, `program`, `cohort` of that program, `registrationType` (`FIRST_TIME`, `SECOND_PROGRAM`, `TRANSFER`), `status` (`ACTIVE`, `SUSPENDED`, `DEREGISTERED`, `GRADUATED`), `startedAt` and optional `endedAt`, and one status-history row per change, starting with the creation. |
| AC-3 | IF a student already has an `ACTIVE` or `SUSPENDED` enrollment in the program, THEN THE SYSTEM SHALL refuse a second one, in the application and in the database. |
| AC-4 | IF the cohort is inactive or belongs to another program, the program is inactive, the start date is invalid, or the NIM is already used, THEN THE SYSTEM SHALL refuse with a field error and write nothing. |
| AC-5 | WHEN an authorized user registers a student, THE SYSTEM SHALL create the person (or attach to an existing person without a student record, matched by national ID or e-mail, leaving their data unchanged), the student, and optionally the first enrollment, in one transaction, link a login account with the same e-mail (as HR-01), and audit it. |
| AC-6 | THE SYSTEM SHALL let an authorized user change a student's personal data and NIM, audit the change with national ID, birth date, phone and address masked, and refuse a national ID or e-mail used by another person. |
| AC-7 | THE SYSTEM SHALL store a year registration per enrollment and academic year with `yearOfStudy` (1 to the program's duration) and a group of the enrollment's cohort for that academic year and year of study, and SHALL refuse a second registration for the same year, a group of another cohort or year, a closed academic year, or an enrollment that is not `ACTIVE`. |
| AC-8 | THE SYSTEM SHALL let an authorized user change a year registration's group, with an audit entry. |
| AC-9 | THE SYSTEM SHALL list students in a PLT-10 table (student number, name, NIM, program, cohort, year of study, group, status) with filters on program, cycle, year of study, group, enrollment status, gender, residence and academic year, within the user's program scope, with national ID, birth date and address never in the list. |
| AC-10 | THE SYSTEM SHALL show a student page with tabs for personal data, enrollments, yearly registrations and status history, hide national ID, birth date and address from users without `stu.student.sensitive`, and answer 404 for a student outside the user's scope. |
| AC-11 | THE SYSTEM SHALL give a student a page with their own record (`stu.student.self`) and nothing of anybody else's. |
| AC-12 | THE SYSTEM SHALL block deactivating a cohort that has active enrollments and a group that has year registrations (ORG-04 dependents) and archiving nothing else. |
| AC-13 | THE SYSTEM SHALL restrict writes to `stu.student.write` (secretary, student affairs), reads to `stu.student.read` (sysadmin, secretary, student affairs, finance, library, quality, head of department, program coordinator; the last two by program scope), identifiers to `stu.student.sensitive` (sysadmin, secretary, student affairs), the own record to `stu.student.self` (role student), and write no personal data to logs. |

### Out of scope

Status transitions after creation (STU-02), applications (ADM-04), login accounts (IAM-02),
grades, attendance, finance (later tabs), documents, photos, the SMIAL exchange (INT-01), import of
existing students (Q-14), lecturer access to their students (needs CUR-04).

### Assumptions

- A student can hold several enrollments (second program, transfer); the one-active rule is per program.
- Registering a student for a year is a separate step from enrolling them (it happens each year).
- `residence` and `birthPlace` are free text now; a controlled list can follow (Q-34).

## 3. Design

### Data model

```prisma
// prisma/schema/students.prisma  (+ Person gets birthPlace?, residence?)
enum RegistrationType { FIRST_TIME SECOND_PROGRAM TRANSFER }
enum EnrollmentStatus { ACTIVE SUSPENDED DEREGISTERED GRADUATED }

model Student { id, personId @unique, studentNumber @unique, nim? @unique, createdAt, updatedAt, createdById, updatedById }

model Enrollment {
  id, studentId, programId, cohortId, registrationType, status @default(ACTIVE),
  startedAt @db.Date, endedAt? @db.Date, createdAt, updatedAt, createdById, updatedById
  @@index([studentId]) @@index([programId, status])
}
// partial unique index: one ACTIVE/SUSPENDED enrollment per student and program

model YearRegistration {
  id, enrollmentId, academicYearId, yearOfStudy, groupId, createdAt, updatedAt, createdById, updatedById
  @@unique([enrollmentId, academicYearId])
}

model EnrollmentStatusEvent { id, enrollmentId, fromStatus?, toStatus, reason?, effectiveDate @db.Date, documentRef?, createdAt, createdById }
```

A database sequence `student_number_seq` feeds `studentNumber`.

### UI

| Route | Who | What |
|---|---|---|
| `/stu/students` | read | table; "New student" for writers |
| `/stu/students/new` | write | person data + NIM + optional first enrollment |
| `/stu/students/[id]` | read (scope) | tabs: personal data, enrollments, yearly registrations, status history; actions for writers |
| `/stu/students/[id]/edit` | write | personal data and NIM |
| `/stu/me` | self | my own record |

### Edge cases & errors

- A person with a national ID only (no e-mail) is matched by the ID; neither given means a new person.
- A student with several programs appears once per enrollment in the list (the list is per enrollment).
- Registering for a year needs a group: the form says so when the cohort has none for that year and links to the groups.
- Concurrent enrollments of the same student in one program: the partial unique index decides.
